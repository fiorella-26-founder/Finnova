BPMN 2.0 Flujo de Atención y Escalamiento de Incidentes (5 Carriles)
ITIL 4 Aligned

El flujo modela la interacción entre los 5 carriles (Swimlanes) de Finnova: desde el reporte inicial, la compuerta de clasificación matricial P1–P4, el diagnóstico y aplicación de workaround temporal en L2, el escalamiento a Control de Cambios y el cierre formal con Post-Mortem (PIR).

Carril 1 Evento Inicio
1. Detección & Reporte

Cliente o Asesor experimenta error y completa el Formulario Extendido con impacto, urgencia y código de error.

Carril 2 Timer MTTA
2. Triaje L1 (Mesa de Ayuda)

Soporte TI valida severidad (P1–P4) en ≤ 15 min. Si es solicitud estándar aplica script L1; si es falla técnica escala a L2.

Carril 3 Workaround L2
3. Diagnóstico L2 / DevOps

Ing. de TI inspecciona logs de Render/TiDB, aplica Workaround temporal para recuperar el SLA (MTTR) y evalúa si requiere RFC.

Carril 4 Rama Hotfix
4. Hotfix L3 / Tech Lead

Si se detecta bug de software, se abre rama hotfix/*, se ejecuta pipeline CI en GitHub Actions y se diseña el Runbook de Pase.

Carril 5 Evento Fin
5. Comité CAB & Cierre

Administrador aprueba pase a producción en Vercel/Render, ejecuta Smoke Test y registra el Post-Mortem / RCA (5 Porqués).

Matriz de Clasificación de Incidentes y Acuerdos de Nivel de Servicio (SLA) Disponibilidad Objetivo: 99.9%
Severidad Criterio de Impacto y Urgencia MTTA (Respuesta) MTTR (Resolución) Escalamiento Obligatorio
P1 - Crítico Impacto Global (Toda la Plataforma) & Urgencia Crítica. Caída pasarela Yape o BD TiDB. ≤ 15 min ≤ 2 horas L2 DevOps → Tech Lead → Comité eCAB (CHE)
P2 - Alto Impacto Global o Departamental con degradación severa. Cold start prolongado (>50s). ≤ 30 min ≤ 6 horas L2 DevOps → Tech Lead → RFC Normal (CHN)
P3 - Medio Afectación parcial de módulo no crítico o subida lenta de vouchers >3MB. ≤ 2 horas ≤ 24 horas Mesa de Ayuda L1 → Soporte L2
P4 - Bajo Problema cosmético visual o consulta técnica sin afectación operativa. ≤ 8 horas ≤ 72 horas Mesa de Ayuda L1 (Atención Directa)
Estrategia de Escalamiento Funcional & Jerárquico
L1
Mesa de Ayuda Inicial (Soporte L1): Atiende consultas, desbloqueo de usuarios (SRQ-ACC) y validación de comprobantes según manual de procedimientos.
L2
Ingeniero de TI / DevOps (Soporte L2): Diagnostica infraestructura en Render y TiDB Cloud, inspecciona métricas de CPU/RAM, aplica workarounds y genera RFCs.
L3
Tech Lead / DBA (Especialista L3): Depura código en caliente, ejecuta DDL en base de datos y compila artefactos en ramas de emergencia.
CAB
Comité CAB & Dirección: Aprueba cambios normales en Ventana FSC o autoriza Pases de Emergencia (CHE) ante fallas P1.

Secuencia Técnica de Pase Backend y TiDB Cloud:
  1. Variables Cifradas en Render: Verificación de DB_HOST (TiDB AWS), DB_SSL=true y JWT_SECRET.
  2. Syntax & Security Check CI: Ejecución de node --check server.js, npm test y npm audit.
