¿Qué es un Cambio de Calendarización (Dimensión Calendario) en Finnova?

En ITIL 4 (Change Enablement / Forward Schedule of Changes - FSC) e Ingeniería de Sistemas, un Cambio de Calendarización controla cuándo y con qué frecuencia se ejecutan procesos o despliegues para no impactar la operación del negocio financiero. En Finnova abarca dos niveles reales:

1. Nivel Automatización / Cron Jobs (Código Real): Modificación o programación de tareas automatizadas por tiempo. Ejemplo en Finnova: scripts/keepAlive.js (Ticket FCC-110) que ejecuta pings cada 10 minutos entre 08:00 y 22:00 h hacia /api/health para evitar el Cold Start en Render.
2. Nivel Gobierno de Releases y Ventanas Operativas (FSC): Reprogramación de Ventanas de Mantenimiento (Domingos 01:00 - 03:00 AM UTC-5, Ticket FCC-111) y períodos de Congelamiento (Code Freeze) del 28 al 30 de cada mes por cierre contable de comisiones (Ticket FCC-112).
Documentación de Pase — FRONTEND (Angular 17 / Vercel) En Repo Git
Archivo en Repositorio: proyecto-finnova/docs/PASE_A_PRODUCCION.md
Pipeline CI/CD: proyecto-finnova/.github/workflows/ci.yml
Secuencia Técnica de Pase Frontend:
  1. Pre-Check CAB: Ticket RFC aprobado en Jira y validación de ventana fuera de Code Freeze.
  2. Configuración Productiva: Verificación de environment.prod.ts apuntando a https://backend-finnova.onrender.com/api y reglas SPA en vercel.json.
  3. Build AOT en GitHub Actions: Ejecución de npm install && npm run build (4 GB Heap) generando artefacto en dist/.
  4. Smoke Test Post-Pase: Validación de rutas /landing, /login y /dashboard/support-changes.
  5. Plan de Rollback (< 1 min): Botón Instant Rollback en consola de Vercel o git revert HEAD.
Documentación de Pase — BACKEND & BD (Express 5 / Render / TiDB) En Repo Git
Archivo en Repositorio: backend-finnova/docs/PASE_A_PRODUCCION.md
Pipeline CI/CD: backend-finnova/.github/workflows/ci.yml
Secuencia Técnica de Pase Backend y TiDB Cloud:
  1. Variables Cifradas en Render: Verificación de DB_HOST (TiDB AWS), DB_SSL=true y JWT_SECRET.
  2. Syntax & Security Check CI: Ejecución de node --check server.js, npm test y npm audit.
  3. Migración SQL Idempotente: Ejecución automática de CREATE TABLE IF NOT EXISTS tickets_soporte_cambios en src/config/db.js y soporteCambioModel.js sin tiempo de inactividad.
  4. Health Check Post-Pase: Petición GET /api/health y GET /api/soporte-cambios/metricas retornando HTTP 200.
  5. Plan de Rollback (3-5 min): Rollback to previous deploy en Render y script SQL inverso en TiDB Cloud.
